# Piwork roadmap — snapshot 2026-07-22

A GUI desktop shell for the Pi coding agent + a removable Suite of extensions.
Design: `pi-cowork-design.md`. Working notes/state: assistant project memory.

## ✅ Done
- Core shell (Electron): container lifecycle, JSONL bridge, streaming chat, steer/follow-up/abort, command palette, model picker
- OAuth login relay (`/login` via `AuthStorage.login`, browser handoff + code paste)
- Launcher + sessions: recent folders, per-folder session history, resume by path, End·Sessions / End·Home
- In-app theming (presets + per-token color pickers, persisted host-side)
- Resource manager: install/remove/list skills, plugins, extensions — **global (Home)** and **project (folder)** scope; optional `~/.agents` sharing
- MCP connectors: `piwork-connectors` engine + Notion/Slack presets + **Custom** form (any stdio/HTTP MCP server), token config in UI
- **Own the shim (UI-intent side)**: pi-host augments `ctx.ui` with first-class Piwork intents without forking `runRpcMode`
- html/artifact intent → CSP-sandboxed iframe renderer (artifacts drawer)
- Slash-command autocomplete in the composer
- Dev ergonomics: `dev-electron` auto-rebuild+relaunch; dev auto-defaults for suite/agent/gateway

## Open options

### A. Self-authoring loop — ✅ DONE (2026-07-22)
- **Authoring skill** — baked `SKILL.md` ("writing-piwork-extensions"), injected via `additionalSkillPaths`; always available to the agent.
- **Non-restart reload** — always-on `/piwork-reload` command (injected via `extensionFactories`, calls `ctx.reload()`); shell reload buttons now reload live instead of restarting.

### B. Suite features (Cowork parity)
- ✅ **piwork-tasks** (done) — `set_tasks` tool + docked widget, persisted via custom session entries (survives compaction/reload).
- ✅ **piwork-renderers** (done) — shell-side rich tool messages: arg summary + collapsible body with unified-diff coloring.
- ✅ **piwork-artifacts** (done) — polling watcher on `/workspace/.artifacts/`, auto-shows HTML/MD/text via the `showArtifact` intent.
- ✅ **piwork-ask** (done) — `ask_user` tool (choice / yes-no / free text) via ctx.ui dialogs. Future: multi-field forms (needs a first-class `form` intent).
- **piwork-tree** — visual session-tree graph, click-to-rewind. (M, heaviest) — **depends on C**; the one remaining Suite tool.

### C. Finish "own the shim" — command side
- Owned shim currently covers UI **intents**. New **commands** (reload, `get_tree`/`navigate_tree`, in-session package install) still need work — they arrive on stdin, which `runRpcMode` owns. Unblocks piwork-tree and clean reload. (M)

### D. Polish / rough edges
- **Seamless OAuth** — remove the "paste the dead localhost URL" step: publish ports 53692 (anthropic) / 1455 (openai-codex) + set `PI_OAUTH_CALLBACK_HOST=0.0.0.0` in the login container. (S)
- **Remote/OAuth MCP connectors** — browser-auth servers (e.g. Notion hosted `mcp.notion.com`), not just token paste. (M)
- More theme controls (fonts/density, save custom presets); keyboard shortcuts.

### E. Scheduler (deferred)
- Cowork's scheduled tasks. Can't be a pure extension (must fire with no container running). Userland cron first, per design. (M–L)

### F. Open-source release (Phase 4)
- Repo split: `piwork` (shell), `piwork-ui` (lib), `ui-intents` (spec), `piwork-suite` (Suite monorepo). macOS signing, auto-update, CI, README leading with the core/Suite split. (L)

## Notes / dependencies
- **piwork-tree and clean non-restart reload want C first.** Most of A and B are doable now.
- Dev run: `npm run dev` from `packages/shell` now auto-detects suite/agent dirs (override via `PIWORK_AGENT_DIR` / `PIWORK_SUITE_DIR` / `PIWORK_ADD_HOST_GATEWAY`).
- pi-host changes require an image rebuild (`docker build -t piwork-sandbox:spike -f images/Dockerfile .`) + a fresh session; shell (renderer/main) hot-reloads.
- Verification harnesses: `scripts/spike-a.mjs`, `packages/shell/scripts/smoke-{bridge,suite,sessions,connectors,login}.mjs`.
